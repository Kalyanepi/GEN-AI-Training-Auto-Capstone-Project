## 1. System Overview

**Product Name:** RoadGuard AI Copilot
**Tagline:** Accurate. Grounded. Cited. Never Fabricated.

The RoadGuard AI Copilot is a production-grade conversational AI system serving three user personas:
- **Policyholders** — asking coverage questions post-accident
- **Claims Adjusters** — triaging repair cost and total loss decisions
- **FNOL Intake Agents** — guiding first notice of loss intake

The copilot handles **10 functional requirements** across two knowledge modalities:
- **RAG (Semantic):** 9 PDF policy documents indexed in FAISS
- **Structured Lookup:** 2 CSV datasets queried via Pandas tool calls

**Core Design Principle:** The copilot NEVER fabricates. Every coverage answer is grounded in a retrieved chunk with a verifiable citation. Every cost or threshold figure comes from a CSV row — never from LLM parametric memory.

## 4. Orchestration Design (LangGraph)

### 4.1 Why LangGraph Over Basic LangChain

LangGraph provides a **typed stateful graph** with conditional edges. This is critical because:
- A single query may require **multiple tools** in sequence ("Is this a total loss and will rental be covered?" needs total_loss_tool + rental_lookup_tool)
- **Guardrail nodes** must be able to short-circuit the graph before the LLM synthesizes anything
- **Typed state passing** ensures session context, policy tier, and prior citations flow through every node correctly
- **Deterministic routing** — the intent router controls exactly which tools fire; no hallucinated tool selection

### 4.2 Agent State Schema

```python
# agent/state.py
class AgentState(TypedDict):
    # Input
    session_id: str
    user_message: str
    policy_tier: Optional[str]            # standard | premium | elite
    coverage_type: Optional[str]          # collision | comprehensive | liability | um_uim
    vehicle_category: Optional[str]
    state_code: Optional[str]

    # Derived during execution
    detected_intent: Optional[str]
    tools_to_invoke: List[str]
    tool_results: List[ToolResult]
    retrieved_chunks: List[ChunkResult]
    citations: List[Citation]

    # Guardrail flags
    input_guardrail_triggered: bool
    output_guardrail_triggered: bool
    guardrail_reason: Optional[str]

    # Output
    final_answer: Optional[str]
    disclaimer: Optional[str]

    # Observability
    conversation_history: List[BaseMessage]
    trace_id: Optional[str]
    latency_ms: Optional[int]
```

## 5. RAG Pipeline Design

### 5.1 Two-Pass Chunking Strategy

**Pass 1 — Section Boundary Detection:** Split PDFs at section/subsection headers (SECTION 1, subsection 3.1, PART 2, etc.). Each chunk is semantically complete.

**Pass 2 — Size Normalization:** For sections exceeding 600 tokens, apply recursive character splitting:
- chunk_size = 500 tokens
- chunk_overlap = 75 tokens (15% — preserves context across boundaries)
- separators = double-newline, newline, period-space, space

Why this matters: "What does my collision deductible apply to?" must retrieve the complete subsection 3.1, not a fragment that stops mid-explanation.

### 5.2 Document-Specific Chunking Rules

| Document | Rule |
|---|---|
| FullAutoPolicy_RoadGuard.pdf | Split at SECTION + subsection boundaries |
| Declaration Pages x3 | Each coverage row is its own chunk; tier tagged separately |
| FNOL_Intake_Guidelines | Split at PART boundaries; each step block is one chunk |
| UM_UIM_CoverageGuide | Split at PART boundaries |
| RoadsideAssistance | Each service type row chunked individually |
| AutoInsurance_Glossary | One chunk per term definition (natural boundaries) |
| RentalReimbursement | Per-tier reimbursement rules each get their own chunk |

### 5.3 Embedding Strategy

- Model: text-embedding-3-small (optimal cost/accuracy for insurance domain text)
- Batch size: 100 chunks per API call
- Retry logic: exponential backoff on 429/500 (max 3 retries)
- Dimension: 1536, L2-normalized before FAISS insertion
- Estimated corpus: approximately 260 chunks total

### 5.4 FAISS Index Configuration

- Index type: IndexFlatIP (Inner Product on L2-normalized vectors = cosine similarity)
- Why Flat over IVF/HNSW: At ~260 chunks, flat index builds instantly, query latency under 5ms, zero accuracy penalty vs approximate methods
- Persistence: index.faiss + index.pkl mounted as Docker volume — survives container restarts

### 5.5 Metadata-Filtered Retrieval

FAISS does not natively filter, so we over-retrieve then post-filter:

```python
def retrieve(query, coverage_type=None, policy_tier=None, top_k=5):
    query_vector = embedder.embed(query)
    # Over-retrieve 4x to have candidates after metadata filtering
    candidates = faiss_index.search(query_vector, k=top_k * 4)
    # Apply metadata filters
    filtered = [c for c in candidates if matches_metadata(c, coverage_type, policy_tier)]
    return filtered[:top_k]
```

Why metadata filtering prevents hallucination: If policy_tier="premium", retrieval is filtered to chunks tagged ["premium", "all"]. The system will never serve Elite deductibles ($250) to a Standard user ($1,000).

### 5.6 Anti-Hallucination Threshold

If no chunk scores above similarity 0.65:
> "I don't have specific policy language on that in my documents. Please contact your RoadGuard adjuster at 1-800-555-0600 for an official answer."

No citation is fabricated. No answer is synthesized from LLM memory.

```
  1. Pandas lookup: state_code + vehicle_age_bucket -> threshold, salvage_pct
```

## 8. Memory Strategy

### 8.1 Two-Tier Architecture

**Tier 1 — Conversation Buffer (Short-Term)**
- ConversationBufferWindowMemory(k=10) per session
- Stores last 10 user+assistant pairs
- Enables: "my car" -> Toyota Camry Mid-size Sedan from 3 turns ago
- Location: In-memory Python dict keyed by session_id

**Tier 2 — Session Context (Extracted Structured Facts)**
```python
class SessionContext(BaseModel):
    session_id: str
```

## 11. Guardrails Strategy

### 11.1 Input Guardrails (Pre-Agent)

| Guardrail | Method | Block Code |
|---|---|---|
| PII Detection | Regex (SSN, credit card, DOB) + optional Presidio library | PII_DETECTED |
| Prompt Injection | Keyword patterns + LLM classifier | PROMPT_INJECTION |
| Off-Topic Filter | LLM: "Is this an auto insurance question?" | OUT_OF_SCOPE |
| Jailbreak | Patterns: ignore instructions, pretend, act as, DAN | JAILBREAK_ATTEMPT |

### 11.2 Output Guardrails (Post-Synthesis)

| Guardrail | Method | Block Code |
|---|---|---|
| Legal Advice | LLM check + keywords: legally liable, sue, lawyer | LEGAL_ADVICE |
| Fault Determination | Pattern: at fault, not your fault, responsible for | FAULT_DETERMINATION |
| Citation Requirement | Structural: coverage answers must have 1+ citation | MISSING_CITATION |
| Fabricated Cost | Cross-check: dollar figures must match CSV within 10% | FABRICATED_DATA |

## 13. Evaluation Framework

### 13.1 30-Question Test Dataset

**10 Coverage Q&A (FR-01, FR-02):** Collision vs comprehensive classification, exclusions (wear and tear, intentional acts), GAP eligibility by tier, MedPay limits, UM stacking, liability limits per tier, glass deductible waiver

**6 Repair Cost Estimation (FR-03):**
- Front bumper replacement — Mid-size Sedan — Collision
- Airbag dual deployment — Luxury SUV — Collision
- Windshield replacement — Compact SUV — Comprehensive
- Full hail damage — Economy/Compact — Comprehensive
- Engine damage — Full-size SUV/Truck — Collision
- Frame straightening major — Mid-size Sedan — Collision

**5 Total Loss Determination (FR-04, edge cases):**
- IL: ACV=$8,000 repair=$6,500 -> 81.25% > 75% -> total loss
- TX: ACV=$12,000 repair=$11,000 -> 91.7% < 100% -> NOT total loss (TX actual rule)
- FL: ACV=$5,000 repair=$3,800 -> 76% < 80% -> NOT total loss in FL
- PA: ACV=$10,000 repair=$10,500 -> 105% < 110% -> NOT total loss in PA
- CA: ACV=$15,000 repair=$12,000 -> 80% > 75% -> total loss in CA

**5 FNOL Guidance (FR-05):** Standard collision FNOL, hit-and-run (72hr UM deadline), theft (police report 24hr), hail comprehensive, third-party liability scenario

**4 Rental/Roadside (FR-06):** Premium rental limit, Elite lockout unlimited, Standard towing 2x/term, Elite trip interruption $600/incident

## 15. Security Considerations

| Threat | Mitigation |
|---|---|
| API key exposure | All keys in .env, injected as env vars at runtime. Never in code or Dockerfile. .gitignore covers .env |
| Prompt injection | Input guardrail catches patterns before agent invocation |
| PII in conversation | Input guardrail blocks SSN, DOB, credit cards. All session data ephemeral — nothing persisted to disk |
| SSRF / code execution | LLM output never executed as code. Tools return structured data only |
| Unauthorized API access | Rate limiting middleware (30 req/min). API key auth header for production |
| Container attack surface | python:3.11-slim base image, minimal layers, non-root user in Dockerfile |
| AWS exposure | Security group: port 22 restricted to known IP. Port 80 public. No hardcoded credentials anywhere |

## 19. Engineering Standards

### 19.1 Configuration — Never Hardcode

All values in api/config.py via pydantic_settings.BaseSettings. Every threshold, model name, path, limit, and timeout is a configurable environment variable with a sensible default. Team members change behavior through .env, not by editing code.

### 19.2 Async Patterns

- All FastAPI routes: async def
- All tool _run() methods: async def
- OpenAI calls: AsyncOpenAI client
- CSV lookups: synchronous Pandas (CPU-bound, wrapped in run_in_executor if needed)

### 19.3 Error Handling Pattern (All Tools)

```python
async def _run(self, **kwargs) -> ToolResult:
    # WHY: structured ToolResult returns allow the orchestrator to decide
    # whether to retry, use a fallback tool, or surface a safe message —
    # instead of letting exceptions bubble up to the user as 500 errors.
    try:
        result = await self._execute_core_logic(**kwargs)
        logger.info("tool_success", tool=self.name, latency_ms=elapsed)
        return ToolResult(success=True, data=result)
    except DataNotFoundError as e:
        # WHY: data not found is expected (unknown state, unrecognized damage type)
        # Handle gracefully with a fallback, not an error
        logger.warning("tool_no_data", tool=self.name, reason=str(e))
        return ToolResult(success=False, error="Data not found",
                          fallback_message=self.get_no_data_message())
    except Exception as e:
        # WHY: unexpected errors must never expose stack traces to users
        logger.error("tool_error", tool=self.name, error=str(e), exc_info=True)
        return ToolResult(success=False, error="Internal error",
                          fallback_message="Please contact your adjuster directly.")
```

### 19.4 Comment Standard — Why Not What

```python
# WHY: We fuzzy-match damage_type because users say "bumper hit" or
# "my hood got dented" — not the exact CSV label "Hood dent repair".
# difflib.SequenceMatcher at 0.60 handles common paraphrases without
# false positives on unrelated damage types.
damage_match = find_best_damage_match(damage_type, csv_damage_types, threshold=0.60)
```
